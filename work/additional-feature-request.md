# 汎用 追加Feature Request集

初版の要件定義書に無く、開発の途中で追加された要望を、他リポジトリーでも使える形に一般化したもの。

## 1. 最適化・計画
- **ワンクリック最適化**: 割当・資源・要員を一括で再計画する推奨機能を、何も入力しなくても使える形にする。同じ入力からは同じ結果になる。
- **優先度と制約の設定**: プリセット（バランス、SLA優先、省資源、時間優先）と重み（0〜10）を選べるようにする。計画期間・バッファ・移動距離・同時作業数などの制約も指定できる。設定を変えたら古い結果は破棄する。
- **説明可能な結果**: 実行の前後比較、変更一覧とその理由、解決できなかった項目を表示する。
- **非破壊と監査**: 元データは変更せず、出力には派生物と明記する。実行ごとに監査ログを残す。

- **最適化の入力要素**: 顧客・契約上のSLA優先度、期限までの時間、拠点間の距離、資源の上限（1資源1タスク、同時作業数）、作業間バッファ、閉鎖・天候などの制約を、重みまたは厳守条件として扱う。着手済みの作業は凍結する。
- **ローリングホライズン方式の貪欲ヒューリスティック**: 優先度順に割り当てる決定的な手法を最初の実装とする。本番ではソルバーへ置き換える前提とする。

## 1b. ドメインモデル・運用データ
- **業務エンティティと運用 KPI**: 設備・路線・稼働量などのエンティティと、SLA 目標を持つ KPI を定義する。例外に対するアクション行を算出する。
- **ライブフィードとタスク管理**: 状況をシミュレートして表示する。決定から派生したタスクに担当者を付けて管理する。

## 2. 実行基盤・再現性
- **ローカル完結モード**: 外部APIやクラウドを使わず、localhost だけで全機能が動く。リモート呼び出しを設定で有効化できないようにする。
- **ルールベース固定の推奨**: LLM を使わず、決定的なルールだけで推奨を出す。
- **人による承認ゲート**: 提案は、権限のある役割が明示的に承認するまで反映しない。承認と監査はローカルに保存する。
- **時計の一元管理**: `Date.now()` を使わず、時刻と ID の生成を1つのモジュールに集約する。`?clock=<ISO>` で時刻を固定でき、テストも再現できる。
- **クラウドデプロイ自動化の無効化**: 過去のインフラ資産は参照用に残し、現行構成には含めない。
- **受け入れ要件の明文化**: 「localhost だけで全機能が動く」「同じ入力で同じ結果」「承認前は決定を変えない」「クラウド自動化は無効」を、ID 付きの受け入れ条件として定義する。
- **クラウド構成の追加**: 静的 Web アプリのデプロイ設定、Bicep によるインフラ定義、予算監視と通知、AI プロジェクトのエンドポイント設定を用意する。ローカル専用モードとは分離する。

## 3. UI・可視化
- **多言語対応**: 言語切替コンポーネントを用意する。翻訳の網羅をテストで強制する。
- **D3 による KPI・価値の可視化**: リングゲージで KPI を表示し、前後比較を棒グラフで表示する。
- **地図のホバーとポップアップ**: 地図上のエンティティにマウスを載せると詳細を表示する。
- **ライブフィードバーとタスク一覧**: 状況の更新をリアルタイムに表示する。決定から派生したタスクを担当者付きで管理する。
- **使い方ガイドと実行ヒント**: 最適化画面などに使い方、容量レポート、サマリーを表示する。

## 4. データ・顧客切替
- **外部公開データからのプロファイル自動生成**: Wikipedia、Wikidata、OpenStreetMap から施設情報を収集する。決定的なサンプルデータを足してプロファイルを生成し、検証して保存する。
- **顧客固有値の外出し**: 顧客名・通貨・前提を設定ファイルに集約し、コードに直書きしない。
- **位置追跡の永続化**: 位置情報を IndexedDB に保存し、再生できる。

## 5. 品質・テスト
- **ゴールデンスナップショット・プロパティ・カバレッジ**: ドメイン層で 80% 以上を維持する。
- **E2E テスト**: Playwright で一通りの画面操作を検証する。
- **スタブ時刻での再現テスト**: テスト時は時刻を固定する。

## 6. 連携・エージェント
- **ドメインエンジンの MCP 公開**: エンジンのツールを MCP サーバーとして公開する。スモークテストと決定性のテストを付ける。
- **モデルの選択肢を検証する**: モデルに数値を作らせず、エンジンが出した選択肢から選ばせる。選択した ID はエンジンのリストに対して検証する。

## 7. ドキュメント・資料
- **README の整備**: バッジ、概要、機能、クイックスタート、アーキテクチャ図、ワークフロー図を載せる。
- **システム構成図**: コンポーネント構成を Mermaid で示す。
- **ステークホルダー別の資料**: 経営層向け、CIO/CTO 向けのデッキを作る。デモ台本には視覚的なハイライトと事前確認手順を入れる。
- **案件・顧客向けのプレゼン資料**: 案件の背景、取り組み、アーキテクチャを説明するナラティブ資料を用意する。
- **Well-Architected 分析レポート**: 日本語版も用意する。
- **Copilot 利用分析レポート**: 日本語版も用意する。

## 8. 開発体験
- **タスクランナー連携**: VS Code のタスクで開発サーバーをバックグラウンド起動できる。
- **カスタムエージェントとスキル**: シナリオ追加、顧客切替、言語追加、デッキ生成などの定型作業をスキル化する。
- **AGENTS.md と Copilot 指示**: ハードルールとコマンド一覧を明文化する。
