「Great」をさらに高めるには?

# 統合された運用データ基盤
全般

解決すべき課題 / 実現すべき機会

課題
•  運用データが GroundStar、G-Ops、Mosaic、DSM、iFleet、BRS、TOMS、さらに CAG と航空会社のフィードに分散している
•  SIOC、BU Ops、Ground Ops にまたがって、需要、キャパシティ、アセット、例外を単一のリアルタイムビューで把握できない
•  アナログなプロセス (無線、WhatsApp、紙) により、データに抜けが生じている

現在の解決方法
•  ポイントツーポイントのインターフェース。EDH / DataNexus をハブとして整備中
•  デューティマネージャーが、意思決定やレポートのために手作業でデータを集約している

何もしないことのリスク
•  新しい AI やダッシュボードの取り組みのたびに独自の統合を再構築することになり、遅く、高コストで、一貫性がなくなる
アイデアは?

ユースケースの説明
Microsoft Fabric をリアルタイムの運用データプラットフォームとして EDH / DataNexus を拡張する: すべてのシステムが、ガバナンスの効いた 1 つの OneLake に対して書き込み・読み取りを行い、フライト、タスク、アセット、天候のストリーミングイベントを扱う。

仕組み
•  Eventstreams が、フライト、ターンアラウンド、タスク、GSE、天候のイベントを数秒で取り込む
•  共通データモデルを 1 つに統一: フライト – ターンアラウンド – タスク – アセット
•  既存の EDH ストアへのショートカットとミラーリング — 全面的な置き換えは不要
•  Microsoft Purview による、BU 単位のガバナンス、リネージ、アクセス管理

MICROSOFT ソリューションコンポーネント
Microsoft Fabric (Real-Time Intelligence、OneLake、Data Factory)、Microsoft Purview

データとシステム
GroundStar、G-Ops、Mosaic、DSM、iFleet、BRS、TOMS、CAG のターンアラウンドイベント、航空会社の CPM、気象サービス

# 障害予測およびリカバリーオプティマイザー
全般

解決すべき課題 / 実現すべき機会

課題
•  フライトの遅延、雷雨や落雷による作業停止、到着便の遅れが、シフトをまたいで連鎖する
•  2 時間以内の変更に対する再計画は手作業で、一部のベテランスタッフに依存している — 労働力の高齢化
•  スタッフと GSE の再配置は、障害が発生する前ではなく、発生した後に行われる

現在の解決方法
•  デューティマネージャーが、電話と無線で GroundStar の配置と SIOC の優先順位を調整している
•  気象や到着便の遅延確率といった予測シグナルがほとんど活用されていない

何もしないことのリスク
•  取扱量が増え、専門知識を持つ人材が退職するにつれて、残業、遅延、SLA ペナルティが増大する
アイデアは?

ユースケースの説明
数時間先の障害を予測し、リカバリーを推奨する: Azure AI がフライトごとに遅延と気象による作業停止のリスクをスコアリングし、オプティマイザーが 2 時間以内の変更に対するスタッフ、タスク、GSE の再配分を提案し、人が承認する — 置き換えではなく、取り囲む。

仕組み
•  フライトの履歴、出発地と目的地の天候、CAG のマイルストーンに基づく遅延リスクモデル
•  ランプ作業向けの、気象による作業停止のナウキャスト (落雷、大雨)
•  制約オプティマイザーが、スタッフ、タスク、GSE を再配分する
•  コントロールタワー内での what-if シナリオ。Teams を通じた承認

MICROSOFT ソリューションコンポーネント
Azure Machine Learning、Azure AI Foundry、Fabric Data Science、Azure 上の最適化ソルバー

データとシステム
ユースケース 1 のプラットフォーム: 12〜24 か月分のフライト、遅延、天候、タスク、作業停止のデータ。GroundStar RT

# コネクテッド GSE とアセット稼働率
全般

解決すべき課題 / 実現すべき機会

課題
•  カート、ドーリー、GSE は計画シートで事前に割り当てられる。到着が遅れると、アセットが拘束されたまま遊休状態になる
•  機材の所在が分かりにくく、スタッフがエプロンを探し回っている
•  アセットの追加はコストがかかり、エプロンのスペースにも制約される

現在の解決方法
•  動力付き GSE には iFleet を使用。動力なし機材のトラッキングを導入中
•  計画シート、無線、経験に基づく割り当て

何もしないことのリスク
•  スループットを上回る速さでフリートが増え、設備投資と減価償却が増加する
アイデアは?

ユースケースの説明
すべての GSE ユニットとカートをリアルタイムで追跡し、動的に割り当てる: IoT の位置情報とステータスが Fabric にストリーミングされ、AI がライブの ETA に基づく割り当てを推奨し、牽引の指示がモバイルデバイスに届く — 計画ベースから、リアルタイムのアセット運用へ。

仕組み
•  IoT トラッカーが位置情報とステータス (利用可能、待機中、使用中) をストリーミング
•  コントロールタワーでの、ピアごとのライブアセットマップ
•  ETA / ATA とターンアラウンドの必要性に基づく割り当ての推奨
•  使用状況とテレメトリーからの予知保全シグナル

MICROSOFT ソリューションコンポーネント
Azure IoT Hub / Event Hubs、Fabric Real-Time Intelligence、Azure Maps、Azure Machine Learning、Power Apps

データとシステム
